# Evaluation diagnosis (Phase C) — MEDDOCAN dev

**Date:** 2026-09-19. **Split:** `dev` (250 documents). `test` is not touched.
Evidence generated by `eval/diagnose.py` → `eval/results/diagnosis.json`.

## 1. ID/PHONE confusion

Gold → pred confusion matrix (class of the first overlapping prediction), class
**ID** (support in dev: 745):

| Pred | Before | After |
|---|---|---|
| ID | 7 | **710** |
| PHONE | 715 | **13** |
| (FN) | 13 | 12 |
| SEX | 7 | 7 |
| others | 2 | 3 |

**Root cause (two mechanisms):**

1. The phone regex `[3456789](?:[\s.-]?\d){8}` absorbed identifiers with format
   "XX XX NNNNN" (`28 28 20943`, `50 50 98653`) because they are 9 digits with
   separators starting with 3–9.
2. The BERT model labels NHC/DNI as `NUMERO_TELEFONO` (PHONE); the identifier
   regex did detect them as ID, but `detect()` discarded the regex because BERT
   won every overlap.

**Fix:** phone regex bounded to 9 digits starting with 6/8/9 (with optional
`+34`/`0034`); identifiers with concrete formats (DNI/NIE with valid letter,
labelled NHC, "XX XX NNNNN", "XX-NNNNNNNN-XX", CIP, SS, plain 6–10 digits);
most-specific rule wins the dedup; and a BERT/regex disagreement rule (see §6).
The residual `ID → SEX` (7) corresponds to annotation errors in the gold itself
(`lactante`, `blanca`, …) and a handful of names BERT labels SEX.

## 3. Whitelist (`lista_blanca.txt`)

Reviewed term by term. **Removed:**

- `ANA` — given name "Ana"; it blocked anonymizing patients named Ana. The
  clinical concept remains covered by `anticuerpos antinucleares` (kept).

There are no other surnames, toponyms or identifiers in the list: `barcelona`,
`Hamilton` and `Young` were already removed in the first pass. The 2–3 letter
acronyms (`RE`, `VO`, `OD`, `EA`, `FA`, `AP`, `AB`, `NP`, `TB`, `DM`, `HTA`,
`EPS`, `PV`) are kept: they are clinical abbreviations and the name patterns
require ≥ 3 uppercase letters or ≥ 2 words, so they cannot be confused with a
name.

## 4. Over-redaction

% of altered non-PHI tokens (combined, dev): **2.3 % → 1.7 %**.

- The hospital regex now requires a case-sensitive proper noun after the head,
  drops `H.` (it caught «H. pylori») and adds `Complejo Hospitalario`/`Centro de
  Salud` (improves HOSPITAL recall).
- `name_single` (new) only fires on lines with `nombre/nom/apellidos/cognoms`.
- Note: the per-rule count in `eval/diagnose.py` is *raw firing* and
  overestimates `name_single`/`name_mixed` because it does not reproduce their
  context gating; the real figure is the 1.7 % combined rate.

## 5. Detector changes (`src/anonymizer.py`)

- `phone`: bounded to Spanish/international formats (9 digits 6/8/9).
- `IDENTIFIER_PATTERNS`: DNI/NIE with valid letter, SS, CIP, labelled NHC,
  NHC "XX XX NNNNN" and "XX-NNNNNNNN-XX", and a `plain` fallback (6–10 digits,
  excluding phone-like ones).
- `_hospital_spans`: head + case-sensitive proper noun.
- `doctor`: `Doctor`/`Dr:`/`Dra:`.
- Names: signature triggers and `name_single` on name lines.
- Dedup by **priority** (most specific wins), not by length.
- `detect()`: BERT/regex disagreement rule (see §6) + optional Presidio.

## 6. BERT/regex disagreement rule (documented)

When BERT and regex disagree on the label over the same span:

- **Regex wins** on the deterministic classes `{EMAIL, URL, ID, DATE, TIME,
  PHONE}`: concrete formats are more reliable than the model (which fragments
  emails and confuses NHC/DNI with phone). Exception: if regex says PHONE and
  BERT says ID, BERT wins (an ID is not demoted to phone).
- **BERT wins** elsewhere (NAME, LOCATION, HOSPITAL, SEX, AGE, …), where it is
  more reliable than the rules.

## 7. Ablation and decision (dev, 250 documents)

| Configuration | Relaxed F1 | Word F1 | Neutr. | Wide leakage | Direct leakage |
|---|---|---|---|---|---|
| regex | 0.7278 | 0.7080 | 0.6509 | 0.828 | 0.820 |
| bert | 0.7472 | 0.8280 | 0.7711 | 0.788 | 0.780 |
| **bert + regex** | **0.7997** | **0.8548** | 0.9083 | 0.104 | 0.068 |
| bert + regex + Presidio | 0.7478 | 0.8198 | **0.9502** | **0.084** | **0.048** |

With the protocol criterion (relaxed F1 on dev, wide leakage as tie-breaker),
the frozen configuration is **BERT + regex** (no Presidio). Presidio lowers F1
because `es_core_news_lg` over-redacts; since Pukara's use case assumes already
pseudonymised text, the marginal leakage gain does not compensate. Presidio
remains an **actionable extra** (`PUKARA_ENABLE_PRESIDIO=1`) and its standalone
form is referenced from `ramsestein/presidio_carmen`.

## 8. Presidio (actionable extra)

- `src/presidio.py` lazy-loads spaCy `es_core_news_lg`.
- Integration limited to `NAME`/`EMAIL`/`LOCATION`, gap-filling only.
- Measured change on dev: neutralization 90.8 % → 95.0 %, wide leakage
  10.4 % → 8.4 %, at the cost of relaxed F1 0.80 → 0.75.
